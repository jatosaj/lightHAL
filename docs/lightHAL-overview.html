How /lightHAL hands work to a Claude cloud session

You type a task. Your local Claude starts a brand-new cloud session with that task, the session works on its own copy of one GitHub repo and pushes its own branch, and your local Claude picks the result up from GitHub. Placeholders in capitals are yours to fill in.

3 · Why it is built this way

A new session per job, not a message

Asking an already-running cloud session by message counts as "another session asked", and its safety checks block anything that looks sensitive. It also can't reply. Starting a new session with the task as its first prompt makes the task yours, and the "done" commit replaces the missing reply.

One pad, trusted once

Claude Code asks you to trust each folder once, and a trusted parent folder doesn't cover a clone inside it. So every job uses the same folder, emptied and re-cloned each time. Only the ~10-second launch takes turns; the sessions themselves run in parallel.

Never launched from your own checkout

claude --cloud clones the current folder's GitHub remote. A working copy can have several remotes, and one may point at a repo you don't own. The pad has exactly one remote, and a fresh clone carries no other repo's history.

The cloud session sees

  • Everything pushed to the one repo it was started on
  • That repo's own CLAUDE.md and .claude/ skills and settings
  • Your task text

The cloud session does not see

  • Unpushed work, gitignored files, credentials
  • Your local ~/.claude config, commands and memory
  • Your local network, or any other repo
